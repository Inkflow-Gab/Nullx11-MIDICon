# Nullx MIDICon Web Studio

A complete browser workspace for turning audio into playable piano MIDI. It adds a FastAPI + SQLite job backend and a React/Vite studio around this repository's transcription research.

## What works

- **Audio/video upload:** MP3, WAV, M4A, MP4, FLAC, OGG, OPUS, AAC, WEBM, AIFF, MOV, WMA (decoded with FFmpeg). Default limits: 100 MB and 10 minutes of analyzed audio.
- **YouTube audio import:** paste a public `youtube.com` / `youtu.be` video link. The server fetches audio with `yt-dlp`, shows download/extraction progress, then transcribes it. Playlist-only, private, live, and sign-in-challenge videos are rejected with actionable messages. Only import music you own or have permission to use.
- **Two real neural engines:**
  - **Piano specialist** — Kong et al. high-resolution note-only ONNX model, 50% overlapping context windows cross-faded before decoding.
  - **Polyphonic** — Spotify Basic Pitch ONNX model for instrument-agnostic input, mapped to piano.
- **Live job progress:** queued → downloading/preparing → transcribing window-by-window → refining → ready, over Server-Sent Events with polling fallback. Cancel and retry are supported.
- **Playable + editable piano roll:** zoom/seek, upper/lower register colors, synthesized piano preview, original-audio comparison, volume and keyboard spacebar playback. In edit mode you can click/shift-click notes, select all, delete selected notes, adjust velocity, undo/redo, and save the result as a new version. The original conversion stays unchanged.
- **Adjustable output:** sensitivity, shortest note, repeated-note gap merging, transpose, quantization grid, tempo override, dynamics, sustain smoothing, piano-range filtering, single/two-track MIDI.
- **Refine without re-uploading:** reuses the stored neural analysis and source audio.
- **Downloads:** MIDI, JSON note events, CSV, or a ZIP with MIDI + notes + settings + attribution. The library can also export all completed MIDI files in one ZIP with note JSON and a manifest.
- **Private per-browser history:** SQLite-backed jobs isolated by an HttpOnly random session cookie; search, filters, favorites, rename, delete, clear history. This is a private browser workspace, **not** a cross-device account system.
- **Retention:** completed/failed/cancelled jobs and their files are removed after 7 days by default. Active jobs are not auto-deleted.
- **Original demo:** a deterministic additive-synthesis piano piece generated by `scripts/create_demo.py`; no third-party recording.

## Quick start (local)

Requirements: Python 3.11+, Node.js 22+, and network access to PyPI/npm/GitHub for the first setup. FFmpeg is provided by `imageio-ffmpeg` if a system binary is absent.

```bash
python3.11 -m venv .venv
.venv/bin/pip install -r requirements-web.lock
.venv/bin/python scripts/setup_web_models.py   # pinned ~85 MB piano ONNX mirror, checksum verified
(cd web && npm ci && npm run build)
bash scripts/run_web.sh                        # http://localhost:3000
```

`run_web.sh` builds the frontend if needed, installs the piano model if missing, regenerates the demo, and serves the built app + API together on `0.0.0.0:3000`.

### Frontend development

```bash
# Terminal 1 — API
.venv/bin/python -m uvicorn webapp.main:app --host 0.0.0.0 --port 8000 --reload

# Terminal 2 — Vite, proxies /api to the API
cd web && npm run dev                            # http://localhost:3000
```

The Vite dev server accepts the Arena preview host and proxies API calls server-side; browser code never calls a hardcoded localhost backend.

### Docker

```bash
docker build -f Dockerfile.web -t midicon-studio .
docker run --rm -p 3000:8000 -v midicon-data:/data midicon-studio
```

The image builds the frontend, installs locked Python dependencies, downloads/verifies the piano model, runs as a non-root user, and stores jobs/models in `/data`.

## Accuracy: what was measured

A reproducible sanity check on the upstream **paired** `cut_bach.mp3` / `cut_bach.mid` example (20 seconds, 217 reference notes) is included:

```bash
.venv/bin/python scripts/evaluate_web.py
```

Results from this environment (CPU, 2 inference threads):

| Engine / mode | Onset F1 @ 50 ms | Full-note F1 @ 50 ms onset + 20% offset | Notes |
|---|---:|---:|---:|
| Piano specialist, raw overlapping windows | 0.941 | 0.840 | 240 |
| Piano specialist, default cleanup | **0.957** | **0.851** | 220 |
| Non-overlapping 2.5 s chunk baseline | 0.921 | 0.772 | 252 |
| Basic Pitch, default cleanup | 0.724 | 0.209 | 214 |

This is **one reference clip**, not a general accuracy claim. It shows why the piano specialist is the default for piano and why overlapping context plus conservative cleanup matters. The original 60 ms shortest-note default removed real fast notes in this clip; the web default is now 30 ms with a 20 ms repeated-note merge gap.

### Honest limitations

- Clean solo piano works best. Full songs with vocals/drums/distortion can produce extra or missing notes; this version maps detected pitches to piano and does **not** perform source separation or create a verified cover arrangement.
- Tempo and key are estimates. MIDI meter defaults to 4/4. Upper/lower tracks split at middle C; they are registers, not hand assignments.
- The piano ONNX export is note-only. “Sustain smoothing” lengthens releases; it is **not** detected sustain-pedal MIDI CC.
- Browser playback is a lightweight local piano-like synth, not a sampled concert grand. Your DAW/soundfont will sound different.
- YouTube availability depends on the server's outbound network and YouTube's current bot/sign-in checks. The integration does not bypass those checks. In the Arena sandbox used for this build, YouTube's TLS endpoint was unreachable; uploads and the demo were verified end-to-end instead.

## Privacy and operational notes

- Session tokens are random 256-bit values; only SHA-256 hashes are stored in SQLite. Cookie: HttpOnly, SameSite=Lax, Secure when served over HTTPS.
- Mutating API requests require `X-MIDICon-Client: web` and same-origin `Origin` when present. No permissive CORS is enabled.
- Job IDs are validated; downloads are ownership-checked; filenames are sanitized.
- One transcription worker protects CPU/RAM. Each browser may have up to 3 active jobs and 100 stored jobs by default.
- Clearing cookies loses access to the workspace. There is no account recovery. Download important files.
- For a public deployment, put the app behind HTTPS and a reverse proxy with request-rate/body-size limits, monitor disk usage, and configure trusted proxy headers. Anonymous sessions are not a substitute for authenticated multi-tenant accounts.

### Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `MIDICON_DATA_DIR` | `.web-data` | SQLite DB, jobs, models |
| `MIDICON_MODEL_DIR` | `$MIDICON_DATA_DIR/models/kong-piano` | Piano ONNX graph + external weights |
| `MIDICON_MAX_UPLOAD_MB` | `100` | Upload size limit |
| `MIDICON_MAX_DURATION_SECONDS` | `600` | Maximum analyzed audio length |
| `MIDICON_RETENTION_DAYS` | `7` | Terminal-job/file retention |
| `MIDICON_SESSION_DAYS` | `180` | Browser cookie lifetime |
| `MIDICON_MAX_JOBS` | `100` | Stored jobs per browser |
| `MIDICON_INFERENCE_THREADS` | `2` | ONNX intra-op threads |
| `MIDICON_ALLOW_YOUTUBE` | `1` | Set `0` to disable YouTube imports |
| `PORT` | `3000` | `run_web.sh` listen port |
| `BUILD` | `0` | Set `1` to force a frontend rebuild |
| `PYTHON` | `.venv/bin/python` | Python used by `run_web.sh` |

## API overview

Interactive docs: `/api/docs` when the server is running.

- `GET /api/health`, `GET /api/session`
- `GET /api/jobs`, `POST /api/jobs` (multipart `file` + JSON `options`)
- `POST /api/jobs/youtube`, `POST /api/demo`
- `GET /api/jobs/{id}`, `GET /api/jobs/{id}/events` (SSE), `GET /api/jobs/{id}/notes`
- `PATCH /api/jobs/{id}` (title/favorite), `POST /api/jobs/{id}/cancel|retry|refine`
- `POST /api/jobs/{id}/save-edit` (manual note edits → immediately completed `edited` version)
- `GET /api/jobs/{id}/download/{midi|json|csv|zip|audio}`
- `GET /api/library/download` (ZIP of completed MIDI + notes + manifest)
- `DELETE /api/jobs/{id}`, `DELETE /api/history`

## Architecture

```text
web/                     React + TypeScript + Vite studio (local fonts, canvas piano roll, Web Audio preview)
webapp/main.py           FastAPI routes, session cookie, CSRF/origin checks, SSE, downloads, static app
webapp/store.py          SQLite sessions/jobs, ownership, progress, retention
webapp/pipeline.py       Single-worker queue, cancellation, retry/refine orchestration
webapp/audio.py          FFmpeg decode/trim/preview, silence checks, waveform peaks
webapp/youtube.py        Strict YouTube URL validation + yt-dlp download/progress
webapp/transcription.py  Piano specialist + Basic Pitch ONNX adapters
webapp/midi.py           Conservative cleanup, manual-edit validation, tempo/key estimates, MIDI/JSON/CSV export
webapp/vendor/           Licensed third-party postprocessors and notices
webapp/assets/           Basic Pitch ONNX model + original generated demo
scripts/                 Model setup, demo generation, reference evaluation, local launch
```

The original `instrument_agnostic_amt` research package and CLI remain intact. The web app is a separate CPU-friendly product layer; it does not silently substitute engines or fabricate progress.
